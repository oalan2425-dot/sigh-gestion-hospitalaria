# SIGH 2.0 — prototipo incremental
Extraer en raíz del proyecto original. Se reemplazan solamente routes/web.php, routes/console.php y resources/views/layouts/app.blade.php (copias adaptadas del ZIP recibido). Revisar git diff. No incluye .env ni dependencias. Respaldar MySQL antes de migrar. Ejecutar php artisan optimize:clear, php artisan migrate --pretend, php artisan migrate, php artisan sigh2:rol CORREO admin. Roles adicionales: aseguramiento, admisiones, clinica, laboratorio, farmacia, almacen, finanzas, auditoria, cartera. Asignar únicamente a cuentas autorizadas. Abrir /sigh2. No usar datos reales.
## Alcance y límites
31 catálogos/registros relacionales con alta y consulta, permisos por grupo, auditoría de altas/consultas, controles básicos de stock, camas, tarifa, factura interna y pagos. Los módulos anteriores conservan sus permisos originales (solo autenticación), por lo que NO existe seguridad integral. No hay edición, cierre de estancias, transición de órdenes, firma, exportaciones, gestión de usuarios desde UI, permisos por registro, integración de EPS antigua, RIPS oficial, DIAN, IHCE, notificaciones, ni pruebas de restauración. Los estados se capturan al crear; no representan validación externa. La facturación es de una prestación por factura. No se implementa el flujo completo ni todos los requisitos del documento. No apto para producción. Los IDs de pacientes, médicos y citas referencian tablas originales. No se migra el texto EPS histórico. No se ejecutaron pruebas de Laravel ni MySQL en el entorno de entrega.
